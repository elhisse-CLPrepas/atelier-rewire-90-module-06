# Cas réel du Module 06 — REWIRE-90-PROJECT

## Pourquoi ce cas est utile

REWIRE part d’une intention réelle, d’une fiche candidat et d’une première production web. Le cas montre le cycle complet :

`Intention → Cadrage → JSON → Mini-site → Tests → Git → GitHub → Revue → Preuve`

## Compétences travaillées

- organiser une arborescence ;
- distinguer sources privées et livrables publics ;
- comprendre l’état d’un dépôt ;
- créer des commits lisibles ;
- travailler avec une issue et une branche ;
- ouvrir et contrôler une pull request ;
- conserver des preuves avant la fusion.

## Règle de confidentialité

La fiche candidature originale ne doit jamais entrer dans Git. Elle contient des coordonnées et des signatures. La copie destinée au dépôt doit uniquement contenir les fichiers nettoyés du mini-site, les tests et les documents publics.

## Structure recommandée du futur dépôt

```text
atelier-rewire-90-module-06/
├── README.md
├── .gitignore
├── CHANGELOG.md
├── site/
├── tests/
├── docs/
├── preuves/
└── .github/
    ├── ISSUE_TEMPLATE/
    └── pull_request_template.md
```

## Définition de terminé

- aucun téléphone, email, secret, signature ou document privé ;
- README clair ;
- JSON valide ;
- quatre états testés ;
- site responsive ;
- issue reliée à la pull request ;
- preuve des tests jointe ;
- validation humaine du fond visible ;
- publication traitée comme une décision distincte.

Statut : **PRÊT POUR UTILISATION PÉDAGOGIQUE — DÉPÔT NON CRÉÉ**.
